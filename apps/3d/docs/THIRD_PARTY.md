Vite copies these into `dist/`, and Tauri embeds that frontend directory. Run `node scripts/license-audit.mjs` to write `artifacts/third-party-inventory.json`, including installed versions, copied notices and runtime hashes. This records engineering evidence, not legal clearance.

The tracked [licenses directory](../licenses/) contains full GPLv3, LGPL-2.1, OCCT exception, Draco, meshoptimizer and Tauri plugin texts plus LibreDWG authors. The original OCCT bridge notice is preserved in `vendor/occt/LICENSE`, followed by the full LGPL and exception. The copying script preserves each installed production package's available LICENSE/COPYING/NOTICE files and supplements packages whose npm archive omits full texts. `licenses/LICENSE-SOURCES.json` records immutable upstream download URLs and text hashes; `licenses/SOURCES.json` and `SOURCE-INSTRUCTIONS.txt` record source revisions, archive locations, rebuild/replacement steps and provenance limits. Generated `npm-inventory.json` is deterministic for the installed lockfile/assets and contains package artifact integrity and runtime hashes.

Its npm metadata supplies no `gitHead`; the recorded tag is source provenance, not a verified source/WASM binary match. Draco artifact provenance is pinned by the installed Three.js package and hashes; the bundled README does not identify an exact Draco build revision, and the license snapshot is not claimed to identify it.

Shenzhen 3D is licensed under GPL-3.0-or-later (see [LICENSE](../LICENSE)), the same as ShenzhenPDF and Shenzhen Files. Its source is public, so recipients of a binary can get the corresponding source from the repository; releases should still name the matching source snapshot.

Because the app imports LibreDWG (GPL-3.0, version 3 or later) into its frontend, the combined work is distributed under GPL-3.0-or-later; a separate chunk or worker does not by itself establish a separate-program boundary. See [GPLv3 sections 5–6](https://www.gnu.org/licenses/gpl-3.0.html) and the [GNU explanation of combined programs](https://www.gnu.org/licenses/gpl-faq.en.html#GPLInProprietarySystem). The LGPL, MIT, Apache and other dependency licenses are compatible with this choice as inventoried here, which is engineering evidence, not legal clearance.

For the CAD bridge, preserve copyright and license notices, supply the applicable LGPL texts and exception, and provide the exact corresponding library/bridge source, modifications and applicable replacement/relinking material. Packaging a WASM library does not remove these requirements. The LGPL permits combination under its stated conditions; read [LGPL-2.1 section 6](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.html) and [OCCT licensing](https://dev.opencascade.org/resources/licenses) against the actual shipped binaries and build process.

The attribution/source-information assets ship with the frontend, but they do not themselves deliver or verify all corresponding source and build inputs. Each release should point to the matching source snapshot and the applicable dependency source/build/replacement material, and preserve third-party rights. Source URLs alone are not automatically a complete source-delivery arrangement: verify the delivery route against the applicable license text.

## Native attribution supplement

Run `python3 scripts/native-license-audit.py` to resolve the locked Cargo metadata, copy available registry-source notices into `artifacts/native-notices/`, and create `artifacts/releases/shenzhen-3d-0.1.2-native-notices.zip`. Use `--offline` when those Cargo sources have already been downloaded. The script changes no app/build files, lockfile or `dist/` assets.

The 16 October 2026 snapshot records 428 non-workspace Rust packages and 711 available LICENSE/COPYING/NOTICE/COPYRIGHT/AUTHORS files. It lists normal/build dependency reachability for macOS Intel/Apple Silicon, Windows MSVC, Linux, Android ARM64/x86-64 and iOS device/ARM simulator targets. The inventory includes declared license expressions, crate-version/archive links, Cargo archive checksums, packaged VCS information and copied-file hashes. It is conservative: build tooling, proc macros and other-target packages are included, so this is not proof that all listed code is linked into a particular binary.

`missing-notices.json` identifies 33 crate archives with no available named/referenced license or notice file. No generic text was invented for those entries. The report retains their declared licenses and source/repository locations so the omissions can be addressed against upstream evidence. The supplement is separate from the frontend notices and should accompany native downloads.

OS/SDK libraries, separately downloaded native binaries, installer runtimes, compiler runtime libraries and final app-store terms remain outside these inventories. License expressions and collected files are upstream evidence, not legal clearance or a guarantee that an archive contains every required notice. Corresponding-source delivery and actual per-artifact obligations still require the selected distribution arrangement.
