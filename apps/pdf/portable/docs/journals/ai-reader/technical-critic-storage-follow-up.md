# Technical critic — Collection relocation follow-up

10 October 2026. Focused review of adjustable dynamic storage, relocation integrity, and credential-status integration. No application launch, user credential access, or paid provider call was performed. Final reviewed-scope technical grade: **9.0/10**, with the supported relocation boundary below.

## Findings resolved

- **P1: a late editable save could be deleted after copying.** The original relocation hashed each copy and later deleted the old editable tree. Collection protection returns before the reader writes, so its manifest lock did not cover that interval. `SPDFMacCollectionStoreLocation.mm:95` now transfers the original editable directory inodes by atomic same-volume exchange before publishing the redirect. Old paths and already-open writer descriptors continue to address the moved files. Failed publication exchanges them back; failed reversal retains the destination for recovery. Production regressions cover a save after initial copying, a preopened descriptor, and failure after transfer. Independent Store/Integrity/Cleanup executables exited 0.
- **P1: retry cleanup could discard an older real editable tree.** `SPDFMacCollectionStoreLocation.mm:57` now refuses cleanup of a real nonempty old editable directory and reports its recovery path. Directory enumeration fails closed. Normal completed moves leave compatibility symlinks, so they still remove old payload completely. The regression preserves distinct legacy editable bytes on cleanup retry.
- **P2: saved pre-move aliases could bypass latest-only AI analysis.** The reviewer implemented the focused follow-up in `SPDFMacAIRevisionContext.mm` and `SPDFMacAIAnalysisIntegration.mm`: worker metadata lookup resolves copy aliases, while ordinary source lookup retains its original path matching. Committed Collection notifications carry original, previous and current roots, allowing synchronous invalidation of the old alias and future notifications at the new root. A lazy observer worker resolves roots for restored windows; render checks and UI notification handling do no filesystem resolution. Disabled settings prevent root work, including stale completion callbacks. These implementation changes are identified separately from the independent relocation review.

No blocker was found in finite 50–80 percentage normalization, overflow-safe budget arithmetic, saved-policy merging, or preserving the percentage through mode changes. The host now reads the persisted connection flag for settings status and saves it before refreshing successful authentication UI; it no longer retrieves the Keychain credential to paint launch settings.
