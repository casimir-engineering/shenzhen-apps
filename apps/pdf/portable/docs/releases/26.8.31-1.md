- **Dark mode for every document** — PDFs, EPUB, Markdown
- Colors survive: a red warning stays red, photos never go negative
- Option in Settings to keep image colors in dark mode
- Mermaid diagrams in markdown render with selectable text
- Viewer optimized for GitHub READMEs, with HTML rendering
- Show in Folder opens in Shenzhen Files when it is installed

---


- The dark reading theme now covers every document, not just Markdown. One
  toolbar toggle, or Shift+Cmd+I, darkens PDF, XPS and EPUB pages onto the same
  soft #1E1E1E paper the dark Markdown theme uses, so a PDF tab and a Markdown
  tab look like one product. Pages are remapped by lightness with their color
  left intact, so a red warning box stays red and a blue hyperlink stays blue
  instead of flipping to its complement the way an inverted page does. The
  choice is remembered across launches and applies to every open tab and to
  documents opened later.
- New setting, Settings > Keep Image Colors in Dark Theme (off by default):
  with the dark theme on, leaves photographs and figures in their original
  colors instead of darkening them along with the page. Scanned pages are the
  exception — a scan is one image covering the sheet, so darkening it is the
  whole point and the setting is ignored there rather than quietly leaving the
  document white. Comic archives and image files are never darkened at all.
- Printing, Save as PDF, Copy Page and Copy Page Image never carry the dark
  theme, whatever you are reading: a PDF exports its own original colors, and
  a Markdown document exports its light pages. Everything else about the page
  is what you saw on screen — same margins, same pagination, same text size.
  A file that carried our dark paper would be wrong everywhere else it was
  opened.
- Translate now works on Markdown documents. Select any text and translate it
  from the toolbar or the right-click menu, exactly as on a PDF. Whole-document
  translation stays a PDF feature — it rewrites translated lines back into a
  PDF's own pages — and says so instead of leaving the button greyed out.
- The dark theme darkens the area around the pages too, well below the paper,
  so a page reads as a sheet on a desk instead of blending into its own
  background. PDF pages get a thin border on all four sides in the dark theme,
  replacing the drop shadow no dark background could show. The reading-theme
  toggle now matches the toolbar controls beside it.
- Real-world READMEs render properly. The inline HTML that GitHub projects
  lean on is now understood natively through a strict whitelist: centered
  `<div>`/`<p align>` blocks, HTML headings, badge images sized by their
  `width`/`height`, `<kbd>` key caps, `<sub>`/`<sup>`, and simple HTML tables.
  `<details>` sections render expanded behind a bold summary line. Scripts,
  styles, iframes, forms and event handlers are stripped and never evaluated —
  there is no web engine anywhere in the reader.
- Mermaid, js-sequence and flowchart.js code fences now draw as real
  diagrams — flowcharts, sequence diagrams, pie charts, state and class
  diagrams, and gantt charts — rendered natively, with no web engine and no
  network. The artwork is fully vector, so it stays crisp at any zoom and
  exports to PDF as vector shapes, and every label inside a diagram is real
  text: you can select it, Cmd+F finds and highlights it in place, and it stays
  selectable in the exported PDF. A fence the renderer does not understand
  keeps its ordinary syntax-highlighted code box.
- Shenzhen Files becomes the app's file manager as soon as it is installed,
  with nothing to configure: Show in Folder reveals there instead of in
  Finder, everywhere the app offers it. Settings > File Manager still switches
  back to Finder, an explicit choice always wins over the automatic one, and
  anything that cannot reach Shenzhen Files quietly falls back to Finder.
  Choosing a file stays native — Open… (Cmd+O), the Cmd+Shift+O path prompt
  and every save panel keep the standard macOS panel, because picking a file
  has to hand the selection back to the app and no external file manager can
  return one. Open… now starts in the folder you are most likely to want:
  the current document's, else the last one you opened, else your home folder.
- A corrupt or hostile file size in a release listing can no longer stop the
  updater from downloading. The download's size ceiling overflowed on an
  absurd declared size and came out negative, which cancelled every download
  on its first progress callback — auto-update would have stayed silently
  broken until a manual reinstall. The size is now clamped before it is used.
