1. The decision in one minute

Build a new React Native + Expo + TypeScript application. Share the interface and domain logic with a browser development surface. Keep PDF, EPUB, file-provider access and byte-intensive storage behind small native adapters. Do not port the macOS coordinator, custom window system or handwritten Markdown pagination engine.

The reader shows one document at a time. Groups live on a separate screen. A reader-controls wheel selects commands for the current document through one continuous Tools-down → slide → release gesture. It contains no document/group switching or library navigation. A standard controls list provides an accessible alternative. The corrected interaction and research are defined in the reader controls UX study; previous document-switching wheel reviews are historical and do not validate it. Collection quietly retains local copies and revisions using shared immutable blocks, with visible storage accounting and conservative cleanup.

Ease of AI development is a release requirement: a small UI change must be reproducible in a named scenario, visible immediately, testable without compiling document engines, and accompanied by the appropriate browser and native evidence. This means architectural boundaries and tools, not an in-app chatbot.

2. Reading comes first

Three entry points: Android Open with, Share to Shenzhen Reader, and the in-app system file picker. Cold launch resumes the last readable document; first launch presents Open a document and an unobtrusive sample. Never wait for Collection, thumbnails, a full-text index or every group's documents before painting the reader.

The reading screen has a compact title/source header and reserved bottom reader chrome with Tools and a standard Controls list alternative. Tools is the sole origin for the reader command wheel; down → slide through a family → slide into its command → release selects in one contact. The six families are Navigate, Zoom, View, Find, Notes and Document. The detailed study distinguishes direct commands from tools requiring text or other input. The page viewport ends above the control strip. A tap on unlinked whitespace can hide chrome; links, text selection, scrolling and double-tap zoom win gesture precedence. The labeled Tools origin remains reachable when secondary chrome hides; no preliminary reveal tap is required. TalkBack keeps navigation controls available rather than auto-hiding them. A header Organizer button opens the last organizer destination, with Groups and Collection as ordinary navigation choices and a clearly labeled Search action. Search there is global; Find in the reader searches only its document. No edge-swipe takeover of Android system Back. Back dismisses the topmost sheet/wheel first, then returns through screen navigation; it does not unpredictably switch document history. Organizer Back always returns to its invoking reader and position. On a cold organizer launch without a reader, Back follows the Android task stack. External opens create a reader return target rather than inserting an unrelated last-used document into that stack. Closing a sheet restores focus to its invoking control. Failed switches keep the previous readable document and announce the failure; recovery into a saved copy announces its dated identity.

PDF uses continuous vertical pages, pinch zoom, page entry, text selection and internal links. EPUB defaults to reflowed continuous reading, with font size, line spacing, theme and chapter navigation; reflow retains a semantic locator rather than a fabricated PDF page. Markdown defaults to reflow, supports headings, links, images, code and GFM tables, and keeps horizontal scrolling local to wide tables/code. Pagination/export fidelity with the desktop Markdown engine is not a v1 promise.

Positions are format-specific: PDF page plus normalized viewport; EPUB spine/resource plus locator/progression; Markdown block anchor plus text quote and local offset. Font, rotation and viewport changes re-anchor rather than restore raw pixel coordinates. EPUB progress says “Chapter 3 · 42%”; PDF says “12 of 48”. Older revisions retain their own position and never overwrite the live document's position.

For stable capture, prefer a provider revision token or immutable descriptor. Check available identity/size/modification token before and after reading; retry twice if it changed. Without a provider guarantee, retain the exact captured byte stream, label it “Captured copy · source consistency unverified,” and do not call it a verified original revision. Rendering success or a hash alone cannot certify source consistency. A detected failed/torn read never becomes a visible revision. A complete but consistency-unverified stream may be durably Saved, but cannot replace the preferred verified recovery target. For app-managed staged files the lease prevents mutations, so exact capture is verified.

Each document stores two independent pointers: newestCaptureID is the newest complete, durable capture, including consistency-unverified captures; preferredRecoveryRevisionID is the newest complete capture verified coherent under a stable provider token/descriptor or immutable staged-file lease. “Saved” certifies storage integrity, not provider consistency. Selection follows this table, shared by Collection, History and resume:

History keeps saved captures in chronological order even when the preferred recovery row is older. When an available original is not byte-identical to a verified saved row, show a separate live Original · Latest entry; otherwise merge the live action into that matching row. Exactly one Latest or Latest verified badge exists, or none if only unverified captures exist. Explicitly opening an unverified capture always retains its dated warning. A later verified capture can advance both pointers. An unverified commit advances only newestCaptureID. This avoids silently choosing less trustworthy bytes just because they are newer.

A readable first page is not proof that the whole file has been archived. Source states and archive states are separate: Original / Imported / Original unavailable versus Saving / Saved / Not saved / Paused. Never show Saved until durable storage commits. For external edits, capture versions when reopening/resuming or receiving a supported provider notification; mobile background limits prevent a promise to capture every edit while the app is suspended.

If the original becomes unavailable, preserve the already readable view and use the recovery table for any reopen; offer Find original or Save a copy in a non-blocking sheet. Search only granted provider locations; no promise to scan the entire phone. Verify candidate bytes by hash, and auto-relink only a unique missing-source match. Identical content can share storage while retaining distinct document identities; names alone never merge histories.

3. Groups have their own place

The Groups screen contains named, colored groups and a search field that filters group names only. A group opens a dedicated document list. Browsing a group never changes the reading document. Tapping a document opens it at its saved position and makes that group active.

Create, rename, recolor, reorder, hide/show and delete groups. Each document has one home group in v1; moving changes membership, not content. Hiding removes a group from normal navigation, not storage or global search; Show hidden reveals it. Deleting a nonempty group offers Move documents to General, never Delete files. General behaves like any other group. Rename it and the next unassigned incoming document creates a new General. The explicit “Open into this group” action targets the browsed group; incoming external intents use General.

Group order, membership, visibility, scroll position, active group/document, reader-control layout preferences and reading positions survive process death. Document lists use thumbnails and a short position line. Overflow menus provide Rename, Move, History and Remove from group. Rename changes only the app display name. Move changes home-group membership; Remove from group moves it to General and is disabled in General. Close removes the document from the working set (and its group) but preserves original, Collection and reading position. Reopening a closed retained document puts it in General unless explicitly opened into another group. Archive-only documents need not be in any group until opened. A group is a working set, not the archive itself. The default General has a stable role independent of its label; renaming it clears that role, and the next unassigned open creates a new default. A manually named General is an ordinary group with a “Custom group” subtitle when disambiguation is needed. None of these operations delete original files or retained versions.

4. The reader-controls wheel

The wheel contains current-document reader controls only. Document/group switching remains in the organizer. This corrects the earlier specification's mistaken document-switcher interpretation. See the complete UX study and primary-source comparison for rationale, complete command routes, sequences and test gates.

A visible Tools control occupies reserved reader chrome above the platform's navigation area. A contact starting there displays the upward fan immediately, with no hold timer or initial tap. Slide through one of six fixed families—Navigate, Zoom, View, Find, Notes, Document—then continue into its expanded command fan and release. The same contact selects a command; family selection is not a separate tap. At most eight commands occupy the shared child fan; they are not crammed into the parent's narrow wedge.

The fixed center of Tools anchors the geometry; an off-center finger-down cannot move it toward an edge. In the 360-wide candidate, family lock is radius 90, inward branch correction 62, center cancel 24, and child band 108–160. Layout/capabilities/document identity freeze at down. No action happens on hover, and one valid release creates at most one command. Cancel, interruption, multi-touch or layout change creates none. Adjust zoom and Page scrub support outward continuation into a same-contact value rail, with preview then release-to-commit. Numeric/text entry and system share/print sheets are explicit alternative or additional tool inputs; do not claim opening their panel completes those tasks. Native pinch and page scrubbing remain standard alternatives.

Page-origin contacts stay with the reader even if they cross Tools. The wheel never installs a global long-press, double-tap, two-finger or edge-swipe shortcut. Android system/mandatory gesture insets and iOS safe-area/navigation constraints are respected without excluding or deferring system gestures. A standard controls list has equivalent accessible commands. Actual native arbitration, one-handed reach and the eight-child layout require the device/usability gates in the study; browser appearance does not certify them.

5. Collection: smaller by construction

On first document open, let reading begin, then ask once: “Keep local copies and history of documents you open? Originals stay in place. Copies stay on this device.” Choices: Keep copies / Not now (enable later in Collection → Settings); show the proposed 1 GiB limit and a Change link. Do not retain content before the answer, except temporary bytes strictly necessary to open a shared/non-seekable file. Turning Collection off stops new snapshots/indexing but preserves existing history. Import only documents the user has granted access to; do not crawl another app's recents.

Collection has one row per document, resolving the available original or the recovery target/choice defined in §2. No Latest badge on ordinary document rows. Search combines a thumbnail with highlighted text snippets. Selecting a match opens that exact document/location; History is a separate explicit action. Index only retained bytes after first paint, in cancellable batches, with clear “Text not indexed yet” states. Title search remains immediate. Each text hit carries document ID, exact content/revision identity, locator and index generation. Before navigation compare it with the live source identity. If unchanged, use the original; if changed or unverified, open the retained matching revision with “Match in saved version · date” and an explicit Open latest action. Never apply old offsets to new bytes. Open-document text search and in-reader Find use a separate cancellable in-memory engine search when Collection is off; closing removes it. Locked documents expose titles only until authenticated; no background password prompting.

Global search orders open document titles, group names, open-document text (first five), collected titles excluding already-open documents (first five), then collected text (first five). Results arriving asynchronously do not move the selected item. col: limits to Collection titles/text, including open documents. Show more expands that section. History versions do not flood the default results.

Exact storage, not optimistic compression claims

V1 format: divide original bytes into fixed 1 MiB blocks; SHA-256 addresses unique immutable blocks. A small ordered manifest reconstructs each revision exactly. Identical files and unchanged blocks across revisions share physical bytes. Small documents are one block. Markdown asset files use the same object store and a revision dependency manifest; only granted local assets are retained. EPUB is retained as original ZIP bytes, not an unpack/repack approximation. Password-protected PDFs retain encrypted original bytes.

Whole-file hashing runs in the same background streaming pass as capture. No PDF byte array crosses the JavaScript boundary. Skip compression for v1 binary blocks: PDFs and EPUBs are often already compressed, and a codec is not allowed to delay reading. Small text/metadata can use the platform's standard deflate codec only when measured savings exceed overhead. No custom compression format or chained binary patches.

Fixed blocks intentionally favor simplicity, append-style PDF changes and fast restore. Insertions and ZIP rewrites can reduce reuse. A content-defined chunking upgrade is a separately measured option if the real corpus misses the storage target; version the chunker in each manifest so old revisions stay readable. Content-defined deduplication is an established approach, but its wins depend on the data. Reference design: restic.

No permanent full-file duplicate alongside every chunked revision. Only leased active/incoming working files during handover and a bounded warm cache may duplicate retained bytes. Original-provider opens bypass reconstruction. A cold archived revision may need reconstruction into a seekable file: show a cached preview labeled Preparing saved copy, then enable interaction when ready. Large cold files cannot honestly have an unconditional instant-open guarantee. Even Android's platform PDF renderer requires seekable input. PdfRenderer contract.

Accounting and cleanup

Default archive cap: 1 GiB, configurable to 256 MiB, 1 GiB or 5 GiB, custom or unlimited. Keep a 512 MiB device-space reserve; low space pauses new capture, never reading an already available original. The cap counts physical unique retained block bytes plus manifest/index overhead; the Storage screen separately reports disposable previews, working files and total app-owned bytes. Idle cache has a 128 MiB ceiling. Active/incoming staging and extraction follow the explicit handover budget below and are visible in accounting. Large imports that cannot be staged offer a precise space error and a provider/direct-open option when possible.

Temporary storage category Hard v1 bound / lifetime
Staged or reconstructed working files One active A and at most one incoming B during handover; each ≤512 MiB, known or unknown length. A direct seekable original needs no staged file. Larger files can use direct access if the engine supports them; otherwise explain the staging limit
EPUB extracted resources At most one set per active/incoming document; each ≤512 MiB inflated, including the per-entry limits in §6. These bytes count in temporary totals, separately from the original ZIP
Idle previews/working files/extraction combined ≤128 MiB total; drop unleased extraction/working files first. The active exceptions end when their last lease releases
Block work buffers ≤8 MiB; archive capture reuses the leased source, never creates another whole-file staging copy
Required remaining device space ≥512 MiB after projected new allocations; checked before admission and per block, including permanent archive writes

Peak additional temporary allowance is working(A) + working(B) + extraction(A) + extraction(B) + 128 MiB idle + 8 MiB buffers. Each working/extraction term is zero or at most 512 MiB; it is an upper bound, not eagerly allocated space. Retained archive and metadata are counted separately in total app-owned space. Preflight known file lengths and a conservative EPUB extraction allowance before admitting B; stream unknown lengths with the same bound and reserve checks. If preserving A plus B cannot fit, cancel B, remove its partial allocations, keep A readable and offer Free cache / Choose another file. Other apps can consume space after preflight, so runtime allocation failures follow the same rollback. Only after B emits interactive content does it replace A; release A and reduce unleased caches to the 128 MiB ceiling. A second incoming request cancels the first incoming generation; no third file is admitted. Expiry never deletes an actively leased file. Export can stream blocks without another materialized full file.

Cleanup first drops regenerable caches. Then rank documents by lowest user-open count, breaking ties by oldest last-open time. Remove each candidate's oldest unkept historical revisions before its latest copy; proceed to the next eligible document. Never automatically delete Kept revisions, active reader dependencies, pending exports, or the sole retained copy of an unavailable/import-only document. Also protect preferredRecoveryRevisionID while the original is unavailable or its availability/identity is unknown, even if a newer unverified capture exists: retaining that capture does not replace the verified recovery guarantee. Before evicting a latest copy, revalidate original availability with its granted capability and identity. Unknown, offline, revoked or unverified access is treated as unavailable: protect the last retained copy. Deleting a reference frees bytes only when no other revision owns the blocks. If protected data prevents meeting the limit, pause capture and offer Review storage / Increase limit. Never silently override Keep. Originals are never deleted. Explicit user deletion may remove a protected recovery revision only after naming that loss in the confirmation. Every revision deletion and pointer repair is one repository transaction: recompute newestCaptureID from remaining complete captures and preferredRecoveryRevisionID from remaining verified captures, or set either to null. Apply the §2 resolution table immediately; never leave a dangling pointer or promote an unverified capture to verified.

Storage shows Used, Shared bytes saved, Temporary, Limit, Available on device, and what cleanup would actually free. “Shared bytes saved” compares logical retained revision bytes with physical retained blocks; it is not a compression-ratio promise. Preview cleanup before applying a lower cap. Exclude a document, stop future collection, remove a history, and remove one revision are distinct commands with explicit scope.

Crash-safe write protocol

The foreground TypeScript repository is the single SQLite writer and archive-mutation coordinator; no worker or native adapter writes SQLite. Its single serial command queue owns jobs and mutation order. ArchiveIO issues opaque process-scoped read/stage/GC lease handles and checks them on every byte operation; UI/domain code never handles paths or descriptor integers. Write and hash temporary blocks, flush/close them, atomically rename into the immutable object store, then commit the revision manifest/references, newestCaptureID and (only for a verified coherent capture) preferredRecoveryRevisionID in one SQLite transaction. Publish Saved only after that commit. Crash before metadata commit leaves reclaimable orphan blocks; it never exposes a half revision. GC takes a mutation lease, derives liveness from committed manifests plus active read/export leases, and deletes only unreferenced blocks. Use SQLite WAL with synchronous=FULL, enabled foreign keys and tested migrations. Native IO must fsync block data and affected parent directories before metadata publication; prove actual device behavior with power-loss/fault simulation, not just a rename test. Run bounded orphan recovery off the opening path. Verify reconstruction hashes before presenting/exporting a retained file. Fault-injection tests cover every phase, concurrent capture/delete, cancellation, full disk and missing/corrupt blocks. SQLite transactions do not themselves make external files atomic. SQLite atomic commit.

6. History and comparison

History is a reader sheet/full screen, not a second implementation inside Collection. Collection's History button opens the document using the §2 resolution table with History selected. Saved versions list newest first, with the live Original entry and Latest / Latest verified badge governed by that table; never award Latest to an unverified capture. Selecting an older revision opens it read-only and shows Older version · date in the reader header, with Return to latest (or Return to latest verified when the source is missing). Unverified captures keep their explicit warning. If linked, Latest always resolves the current original; its unchanged bytes need no new revision.

The Android launch scope includes version preview, Keep, Save a copy and missing-original recovery. Compare with Latest and Compare with Previous are the next delivery: on phones use a synchronized A/B toggle plus change list; on tablets/landscape, optional side-by-side panes. Added/removed text and images need labels and green/red marks plus navigation markers. Do not ship an unlabeled pixel difference as a semantic diff. EPUB comparisons use textual/structural locations and images, not unreliable page numbers. The domain contract and fixtures exist from v1; full visual comparison is explicitly outside the first Android acceptance gate.

Engines are adapters, not a new framework

PDF candidate: MuPDF's maintained Android engine through a small native view. EPUB candidate: Readium Kotlin navigator/publication APIs, Swift toolkit later. Markdown: markdown-it + a GFM table/strikethrough/task-list configuration, sanitized into a local WebView with a documented message bridge. Browser Markdown uses the same HTML/CSS; browser PDF/EPUB scenarios may use fixture surfaces clearly marked simulated. Do not imply those fixtures prove native text selection, rendering or DRM.

MuPDF reuse is conditional on a resolved distribution/license decision before adoption; an iPhone plan cannot ignore that gate. If the intended licensing/distribution is incompatible, choose a maintained commercially licensed PDF SDK or another validated engine at the spike, not after building the product around it. Readium provides Kotlin and Swift toolkits; it is not an official ready-made React Native bridge. MuPDF licensing, Readium Kotlin, Readium Swift. DRM-protected EPUBs and unsupported encryption receive a clear unsupported message; DRM work is not in v1.

Create only three native boundaries: SourceAccess, ReaderSurface, ArchiveIO. Expo Modules supplies Kotlin/Swift module and view integration. Expo Modules. Native code handles seekable descriptors, engine lifetime, file IO, hashing and block reconstruction. JS receives identities, metadata, locators and cancellable progress events; no base64 documents or per-scroll-pixel messages. Native reader gestures and wheel animations stay off a busy JS thread.

SQLite is the durable authority through expo-sqlite, owned exclusively by the TypeScript repository. Native ArchiveIO performs immutable byte operations, issues opaque leases and returns validated descriptors; it never changes manifests or SQL. Foreground/resumed jobs only in v1: TypeScript schedules bounded capture/index batches after first content. App backgrounding stops admission, persists a job checkpoint, requests native cancellation and commits only fully completed verified batches while the runtime is alive. No WorkManager/Headless-JS service is required. On resume, replay persisted jobs idempotently; no claim to capture while suspended.

Sequence: SourceAccess acquires the native source/staged-file lease → reader emits first interactive content → repository queues capture → ArchiveIO writes durable blocks under that lease → repository validates generation and commits references and the two conditional capture/recovery pointers in one transaction → UI receives Saved → release capture lease while the reader retains its own lease. A JS refresh cancels its generation and requests release; expiry/disconnect recovery cannot invalidate a still-active native reader lease. Process death invalidates all native handles; startup opens a new process epoch and uses committed references plus validated resumable staging records. Orphan files are recovered later, and GC cannot race a live write/read lease. Only complete source copies resume; partial streams are retried from their still-valid provider or discarded.

Pure domain reducers and policy decisions are shared across platforms and the scenario lab. A browser fake and the real Android repository must pass the same command/observable-state contract suite; Android alone additionally verifies SQL transactions, filesystem durability and descriptor lifetimes. UI never writes ad-hoc SQL. Expo SQLite's web support is currently alpha, so browser storage is explicitly a fixture implementation. Expo SQLite.
