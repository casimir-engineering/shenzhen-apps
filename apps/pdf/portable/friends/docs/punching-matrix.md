Two real online drivers, each behind its own userspace NAT on loopback, reach each other as friends: the transport, the
order with its provisional budgets (5 s of plain checks, 12 s more when exactly one side maps per destination) and every
NAT technique, as the helper runs them in loopback test mode. STUN comes from the host service's own responder on two
ports. No coturn ran, so where only the relay could help, the matrix shows when the driver asked for it; set
`FRIENDS_TEST_COTURN` to see it connect.

endpoint-independent, D for per destination. *Time* runs from the offerer starting its attempt to its first stream,

## The NAT types

| Name | Behaviour (RFC 4787) |
|---|---|
| full cone | endpoint-independent mapping and filtering |
| restricted cone | endpoint-independent mapping, address-dependent filtering |
| port-restricted | endpoint-independent mapping, address- and port-dependent filtering |
| port-restr. no TCP | as port-restricted, but its firewall drops a SYN that crosses its own: no TCP simultaneous open |
| address-dependent | address-dependent mapping and filtering |
| symmetric, seq. | address- and port-dependent mapping and filtering, each new port the next one |
| symmetric, random | address- and port-dependent mapping and filtering, each new port random |

Every address here is 127.0.0.1, so the emulator gives each NAT's public ports one virtual address, its hosts' private
ports another, and the servers a third. A two-port classifier therefore sees an address-dependent NAT as independent, as
it would on a real network.

## What this does not show

- Real routers, carrier-grade NAT, mainland China and cross-border paths: those stay in the M0 real-network matrix.
- The host's signalling: the two drivers pass it over a socket pair, as the host forwards it, and make relay credentials
  as the host does. In production it travels each helper's own connection to the host, which no NAT here would stop.
- IPv6, router port mapping and two hosts behind one NAT: the emulated network has no IPv6, loopback test mode asks no
  router, and each host here has a NAT of its own.
- Run-to-run variation: birthday probing finds a pair with about 99% probability within its budget, so the suite runs
  that pair a second time after a miss.
