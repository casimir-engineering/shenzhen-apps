# tauri-plugin-szfriends

Shenzhen Friends in a Tauri app ([ADR 0015](../docs/adr/0015-portable-core.md) § 4). The plugin gives the windows
the app names (the main window only, in practice) `window.shenzhenFriends`, exactly the `FriendsBridge` the Electron
preload gives Shenzhen 3D's Mac app, so one React UI serves both shells.

| Where | Mode | Talks to |
|---|---|---|
| Windows, Linux | client | the Rust helper (`core-rs/crates/szfriends-helper`), spawned from the app's per-user copy |
| macOS | client | the Objective-C helper the app embeds, shared with ShenzhenPDF, Shenzhen Files and the Electron app |
| Android, iOS | embedded | the core in the app's process, over an in-memory channel carrying the same frames |

`init` registers the commands and a guest script and nothing else; the first `join()`, which the page sends after its
first paint, locates the helper, reads the Enable Shenzhen Friends setting and connects.

## Pieces

| File | What |
|---|---|
| `src/lib.rs` | `init(Config)`, where Friends' pieces are on each system, the window and run events |
| `src/commands.rs` | The bridge's commands, each refused outside the windows the app names |
| `src/host.rs` | One link per app: status, joining windows and their event channels, intents, offered files, links |
| `src/share.rs` | File ▸ Copy Download Link in the app's own menu: when to show and enable it, and its choice |
| `src/drops/` | Dropped files' paths as the system reports them: WebView2, WebKitGTK, the drag pasteboard |
| `src/router.rs` | Replies to the window that asked, snapshots to the window that subscribed, the shared badge |
| `src/validate.rs`, `src/urls.rs` | What a page may send, and the links and settings pages the bridge opens |
| `src/files.rs`, `src/open.rs` | Pictures: the Friends home, animals, dropped and staged files; the file manager |
| `src/link/` | The connection and its states (`mod.rs`); `desktop.rs`, `mac.rs` and `embedded.rs` make one |
| `src/mac_signing.rs` | A team-signed Mac app's check of the helper's signature, and its own Team ID |
| `src/nearby.rs`, `src/streams.rs` | Phones: the native side's nearby discovery and Bluetooth, given to the core |
| `src/phone/` | Phones: the service in the app, Start again, the foreground lifecycle, the key stores, the animals |
| `android/` | Kotlin: `NsdManager`, Bluetooth LE, L2CAP (`nearby/`); Keystore, share sheet (`FriendsPlugin.kt`) |
| `ios/` | Swift: Network.framework, CoreBluetooth (`NearbyPlugin`); Keychain, backups, share sheet (`FriendsPlugin`) |
| `guest/bridge.js` | `window.shenzhenFriends`, in the windows the app names |
| `permissions/default.toml` | `szfriends:default`, every command; for the main window only, with no remote URLs |

The rules are the Electron bridge's (`electron/friends/*.cjs` in Shenzhen 3D) and are tested case for case.
`permissions/autogenerated/` and `permissions/schemas/schema.json` are written by `build.rs` (generated; the
schema exceeds 500 lines) and committed, so a build in a pinned checkout leaves it unchanged.

## Using it

```rust
tauri::Builder::default().plugin(tauri_plugin_szfriends::init(tauri_plugin_szfriends::Config { … }))
```

and a capability, added at setup or in `capabilities/`, granting `szfriends:default` to `["main"]`. On Windows and
Linux the app ships `szfriends-helper[.exe]` beside its executable (Tauri's `externalBin`) and the animal set in its
resources at `friends/animals/`; its installers run `szfriends-helper --handover` after installing (§ 14). On a Mac
the app carries `Contents/Helpers/Shenzhen Friends.app` and the helper's usage descriptions and Bonjour types in its
own `Info.plist`. Development runs name a helper with `Helper::At` and a Friends home of their own with
`Config::state_dir`; the plugin never reads `$SZFRIENDS_STATE_DIR`, and honours `state_dir` only in debug builds and
with its `test-homes` feature (a test build's), so a release build always serves the person's own Friends. An app
with a File menu passes `Config::share_menu` to show Copy Download Link there and sends the choice to
`copy_download_link`. Shenzhen 3D's `docs/FRIENDS.md` § Tauri shows all of it.

**Dropped files.** The page keeps the browser's own drag and drop (it shows where a drop will land); on desktops the
plugin also hears the system's report of the same drop and gives the page each file's path, matched by name and size
(`drop_paths`): WebView2 for the files the page hands it with `postMessageWithAdditionalObjects` (Windows), WebKitGTK's
`drag-data-received` (Linux), the drag pasteboard (Mac), read only once the page received the drop of a drag the
plugin saw over its own window (`drag_over`, which the guest script sends while files are dragged over the page: the
mouse button down and the pointer inside the window), with the button up again and the pasteboard's change count still
that drag's; a drag is read for the one window it was dropped on. A desktop sends a file from where it is and
stages no copy; a drop the system names no file for is refused. Phones give no paths, so the panel stages each
dropped file's bytes, up to `STAGED_DROP_LIMIT` (250 MB) each (`stagedDropLimit` on the bridge), and `stage` refuses
more (a desktop's staged project, 1 GiB). An app that turns on Tauri's own drag
and drop events can report them with `native_drop`.

**Paths on Windows** are drive-letter paths only: a page cannot name a network share (`\\server\share\…`), since
merely reading one would make Windows sign in to that server as the person. Files on a share mapped to a drive letter
work.

## Phones

`Config::embedded` runs the core in the app's own process (`src/phone/`, `src/link/embedded.rs`): the page speaks
the same frames over an in-memory channel to the same Friends service the desktop helper runs. The platform halves
(`android/` Kotlin, `ios/` Swift) answer Rust only; none of their commands is in the plugin's permissions, so no page
can call them.

- **Size.** Phones are nearby only unless the app turns on this crate's `online` feature (the host connection and the
  data-channel stack). With it, the core fits ADR 0015 § 12's 5 MB when the app builds its phones as
  `core-rs/tools/embedded-size.sh` measures: the `phone` profile's settings (`core-rs/Cargo.toml`: opt-level "z", fat
  LTO, aborting panics) in its release profile and `--config core-rs/phone.toml` (the bundled SQLite's flags, the
  ciphers' arm64 backends, packed relocations on Android). Measured on 2026-10-29: Android arm64 4.85 MB with online
  (2.56 MB deflated), 3.10 MB nearby only; iOS arm64 3.14 MB and 1.92 MB. What an app adds around it is the app's: on 2026-10-17 Shenzhen 3D's `phones-size.sh` measured 4.13 MB for
  Friends without online once Friends' capability is declared in `capabilities/` instead of added at run time
  (`Manager::add_capability` links Tauri's capability parser, regex and URL patterns, 2.2 MB on its own).

- **Where.** Android: the no-backup directory (`Context.getNoBackupFilesDir()`), with `Friends/` (the store and
  received files), `FriendsKeys/` and the setting and staged files beside them. iOS: Application Support, with
  `Friends/` marked excluded from backup at every start (Friends stays off when the flag cannot be set).
- **Key.** Android: `FriendsKeys/identity.sealed`, AES-GCM under a non-exportable Android Keystore key (the alias as
  associated data); a file whose Keystore key is gone reads as absent. iOS: a generic-password Keychain item,
  `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, never synchronised. A test home (`Config::state_dir`, debug and
  `test-homes` builds) keeps a 0600 file key, as the `befriend` tool seeds it.
- **Restored store.** A store without its key, or with another identity's, is served by `phone/restored.rs`: the
  list's banner "Friends can't continue from a backup on this device. Start again to set up Friends here: the
  restored conversations are removed, and your friends will need to accept you again." with Start again
  (`reset_friends`), which removes the key, then the store (keeping `received/`), starts afresh and reconnects every
  page.
- **Reset Friends.** Settings' Reset Friends… (`reset_friends` while the service runs) takes the same path
  (`szfriends-helper`'s `service/reset.rs`): the key leaves the Keystore or the Keychain first (if it refuses,
  nothing changes and the reply says so), the Friends host releases the old ID (with online, within 5 seconds;
  offline the reset goes ahead), the service stops, the store goes (received files stay), a new identity's
  service starts with Nearby as it was, and every page reconnects to it.
- **Lifecycle.** `WindowEvent::Suspended` starts a 20-second grace period; after it the service makes received bytes
  durable at a verified offset (its Sleep). `Resumed` dials friends again and resumes transfers (its Wake).
- **Files.** Phones stage dropped and attached files (`STAGED_DROP_LIMIT`, 250 MB); Android's WebView sends the bytes
  as a JSON array, which `stage` accepts. Received files stay private; the hello carries `files.share`, so `show_file`
  is labelled Share… and opens the share sheet (iOS; Save to Files is among its choices) or Save… and Share… (Android,
  through a cache copy and a `FileProvider`). No storage permission.
- **Nearby.** `src/nearby.rs` installs the platform's discovery and radio into the core before it starts. Friends
  asks for Bluetooth, and on iOS for Local Network access, only when the person opens it (`activate`, when the core
  first browses and powers Bluetooth up), never at launch: `BLUETOOTH_SCAN` (never for location), `_ADVERTISE` and
  `_CONNECT` on Android 12+, `ACCESS_FINE_LOCATION` only through Android 11 (`maxSdkVersion` 30). Android 9 and older
  find people over Bluetooth but carry nothing over it (no L2CAP channels there). The host app declares the usage
  descriptions and `NSBonjourServices` (Shenzhen 3D: `src-tauri/friends/ios/Info.plist`), the same as the Mac
  helper's:
  - `NSLocalNetworkUsageDescription`: "Friends uses your local network to find people near you and to send them
    messages and files directly."
  - `NSBonjourServices`: `_szfriends._tcp`
  - `NSBluetoothAlwaysUsageDescription`: "Friends uses Bluetooth to find people near you, and to reach them when
    Wi-Fi can't."
- **Animal set.** Built into the plugin (`build.rs`) and written to `FriendsAnimals/`, since an Android app's resources
  are not files.

`tauri-plugin` copies Tauri's own Kotlin and Swift libraries into `android/.tauri` and `.tauri` when a phone build
runs (ignored by git).

## Locked builds in an app

An app that keeps Friends optional names the plugin from a registry of its own (`registry = "szfriends-pinned"`),
answered by a placeholder unless a Friends build patches it to the pinned checkout (Shenzhen 3D's `.cargo/config.toml`
and `docs/FRIENDS.md` § Tauri). A Friends build resolves more crates than the app's committed `Cargo.lock` holds, so
the app commits a second lock file for Friends builds and moves it with the pin. `tools/host-build.sh`, run from the
pinned checkout, does each step on a copy of the app's package in a temporary directory, with the patch in the copy's
own manifest, so neither the app's lock files nor this checkout's change and no lock file gains `[[patch.unused]]`:

```sh
tools/host-build.sh lock   <app>/src-tauri <app>/src-tauri/friends/Cargo.lock   # once per pin: keeps every version
                                                                                # the app's lock has, adds Friends'
tools/host-build.sh check  <app>/src-tauri <app>/src-tauri/friends/Cargo.lock   # before a release: still fits
tools/host-build.sh vendor <app>/src-tauri <app>/src-tauri/friends/Cargo.lock <dir>
```

A release build copies the Friends lock over `src-tauri/Cargo.lock`, builds with `--locked` and the `--config` that
`tools/host-build.sh config` prints, and puts the app's own lock back. `vendor` is the one `cargo vendor --locked`
pass a build without the network needs (a VM, a clean machine): the app's Friends build with `--sync` of the core's
workspace (the helper) and this plugin's own, into one directory a build then names as its source of crates.io crates.
`CARGO_NET_OFFLINE=true` resolves and vendors from crates already downloaded. Checked on 2026-10-19 with a copy of
Shenzhen 3D's `src-tauri` at `friends-host`: the Friends lock added 54 packages and moved none, `check` passed, and
`vendor` wrote 553 crates with this checkout unchanged.

## Tests

- `cargo test` here: validation over every intent example in `../fixtures/intents.jsonl`, routing, helper files,
  staged names, link URLs, dropped files' matching, the share menu's states, and the link against
  `szfriends-helper`'s own protocol server in memory.
- `node --test guest/bridge.test.mjs`: the guest script in a fake page.
- `cargo test phone` here: the sealed-file and Keychain stores' rules with fake platform halves, Start again and Reset
  Friends over a real store and the protocol server, the grace period.
- Shenzhen 3D's `scripts/friends/phones-reset.mjs`: Settings ▸ Reset Friends… in an Android emulator, with the
  emulator's own taps: a new ID at once, the friends gone, Nearby running again, the ID kept across a restart.
- Shenzhen 3D's `scripts/friends/phones-exchange.mjs`: the phone app in an Android emulator or the iOS simulator and
  `loopback-peer` (`core-rs/crates/szfriends-helper/examples/`) on the Mac exchange a message and a file each way.
- Shenzhen 3D's Tauri smoke runs the real app against real helpers on Windows, Linux and macOS.
- Phones: `cargo clippy --target aarch64-linux-android` and `--target aarch64-apple-ios` check `src/nearby.rs`;
  the Kotlin and Swift compile against Tauri's own sources from the `tauri` crate (`mobile/android`,
  `mobile/ios-api`). They run on a device only inside a phone build of the app.
